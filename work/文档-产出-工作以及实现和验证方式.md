## 二、阶段一：简单模型 MLIR 全链路 (W0~W5)

**做了什么**：手写 2 个 Torch Dialect MLIR 文件（matmul、add+relu），验证 lowering pipeline。

**产出**：`mlir/handwritten/matmul.mlir`、`mlir/handwritten/add_relu.mlir`

**具体命令**：

### 2.2 简单模型导出 (W3)

### 2.3 Lowering + 优化 Pipeline (W4)

**做了什么**：构建可复用脚本 `tools/lower_and_opt.sh`，3 种优化策略对比。

**具体命令**：
```bash
# 3 种 preset
./tools/lower_and_opt.sh mlir/exported/linear_relu.mlir --preset=light       # canonicalize+cse
./tools/lower_and_opt.sh mlir/exported/linear_relu.mlir --preset=default     # fuse+canonicalize+cse
./tools/lower_and_opt.sh mlir/exported/linear_relu.mlir --preset=aggressive  # +generalize+eliminate-empty
```

**关键源码**（`tools/lower_and_opt.sh` 的 pass 定义）：
```bash
PASSES[light]="--canonicalize --cse"
PASSES[default]="--linalg-fuse-elementwise-ops --canonicalize --cse"
PASSES[aggressive]="--linalg-fuse-elementwise-ops --linalg-generalize-named-ops --canonicalize --cse --eliminate-empty-tensors"
LOWERING_PIPELINE="--torch-backend-to-linalg-on-tensors-backend-pipeline"
```

**验证方法**：对比优化前后 `grep -c "linalg\."` 的 op 计数。

### 2.4 优化效果对比 (W5)

**结论**：`default` preset 最优，平均 **25.8%** linalg op 降低。

| preset | 平均降低 |
|--------|:---:|
| light | 0%（无效果） |
| default | 25.8%（最优） |
| aggressive | +6.3%（反效果） |

```bash
  --convert-linalg-to-parallel-loops \
```

### 4.2 自定义 Pass (W10)

**关键源码**（`passes/CountLinalgOps/CountLinalgOps.cpp` 核心结构）：
```cpp

extern "C" ::mlir::PassPluginLibraryInfo mlirGetPassPluginInfo() {
    return {LLVM_PLUGIN_API_VERSION, "CountLinalgOps", "0.1", []() {
        mlir::PassRegistration<CountLinalgOpsPass> reg;
    }};
}
```

**编译 + 加载命令**：
```bash
# 编译
cd passes/CountLinalgOps && mkdir -p build && cd build
cmake .. -DCMAKE_PREFIX_PATH=/home/lwy/download/llvm-project/install
make -j$(nproc)

# 加载
mlir-opt --load-pass-plugin=libCountLinalgOps.so \
    --pass-pipeline='builtin.module(func.func(count-linalg-ops))' input.mlir
```

### 5.2 算子数据流分析 (W14)

**做了什么**：开发 `scripts/analyze_dataflow.py`，用 torch.export 遍历计算图判断融合安全性。

**核心逻辑**（三行判断）：
```python
prog = torch.export.export(model, inputs)
for node in prog.graph_module.graph.nodes:
    node.target        # "aten::mul.Tensor" — 算子名 → 分类
    node.meta['val'].shape  # tensor shape
    list(node.users)   # 下游 consumer → 判断单/多 consumer

# 融合安全性判断：
# 1. len(users) == 1  → 单 consumer ✅
# 2. 全为 ELEMENTWISE   → 无跨库边界 ✅
```

**具体命令**：
```bash
python scripts/analyze_dataflow.py --model gpt2-tiny --block 0 --seq-len 8 --hidden 128
```

**产出**：
- `table_c_subgraph_ops.csv`：每个 op 的类型/shape/consumers
- `table_c_fusion_chains.csv`：可融合的 elementwise 链

**关键发现**：GPT-2 GELU = 7 ELEMENTWISE ops 单链（可安全融合）；residual add 有 2 consumer（不可融合）。

### 5.3 Triton Kernel 手动优化 (W14)

**做了什么**：写 GELU/LayerNorm Triton kernel，融合碎片。

**关键源码**（`triton/gelu_fused.py` 的融合 kernel）：
```python
@triton.jit
def add_gelu_kernel(x_ptr, bias_ptr, y_ptr, n_elements, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offsets = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offsets < n_elements
    x = tl.load(x_ptr + offsets, mask=mask)
    bias = tl.load(bias_ptr + offsets, mask=mask)
    added = x + bias                    # ← 融合：add 在寄存器中
    y = 0.5 * added * (1.0 + tl.math.erf(added / 1.4142))  # ← GELU 也在寄存器
    tl.store(y_ptr + offsets, y, mask=mask)
```

**融合机制**：
```
PyTorch: 8 kernel (mul→pow→add→mul→tanh→mul→add→mul) + 7 中间 tensor
Triton:  1 kernel (全在寄存器) + 0 中间 tensor
```

**验证方法**（表D）：
```bash
python triton/gelu_fused.py     # → table_d_kernel_before_after.csv
python triton/layernorm_kernel.py
```

### 5.4 GPT-2 模块替换 (W14)

**做了什么**：Model Surgery — 替换 GPT-2 内部的 GELU 为 Triton 版本。

**关键源码**（`scripts/patch_gpt2_triton.py`）：
```python
class TritonGELU(nn.Module):
    def forward(self, x):
        y = torch.empty_like(x)
        n = x.numel()
        grid = (triton.cdiv(n, BLOCK),)
        _triton_gelu_kernel[grid](x, y, n, BLOCK=BLOCK)
        return y

# 手术式替换
for block in model.h:
    block.mlp.act = TritonGELU()   # 替换 GELU 为 Triton kernel
```

**验证方法**：
```bash

```

## 附：关键教训速查

1. **导出 API**：`torch_mlir.fx.export_and_import()`，不是 `torch_mlir.compile()`
2. **工具分工**：系统 `mlir-opt` 不含 Torch 方言，必须用 `torch-mlir-opt`
3. **最优 Pass**：`--linalg-fuse-elementwise-ops --canonicalize --cse`
4. **反效果 Pass**：`--linalg-generalize-named-ops`（小模型 +6.3%）
5. **写 kernel 前先做数据流分析**：否则写出 GPT-2 中不存在的 pattern
6. **PyTorch profiler API 版本差异**：`self_device_time_total`（新版）vs `cuda_time_total`（旧版）
7. **GEMM 不可超越**：cuBLAS 占 79% GPU 时间，Triton 收益来自碎片消除而非超越 cuBLAS
