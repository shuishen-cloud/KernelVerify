# 工作划分

## W0：项目结构初始化

- **描述**：
  1. 设计并创建项目目录结构（`scripts/`、`mlir/`、`tools/`、`models/`）
  2. 将现有文件迁移至对应目录
  3. 更新三份文档反映新结构和实际发现
- **输入**：无
- **产出**：标准化目录结构，已整理的文件，更新的文档
- **难点**：低
- **风险**：低
- **优先级**：P0（必须在 W2 前完成）

## W1：环境确认与工具链验证

- **描述**：
  1. 确认 Conda 环境 `novel_llm` 中 torch（2.12.0）、transformers 版本
  2. 确认 mlir-opt 可用性及版本（✅ 已确认：`/home/lwy/download/llvm-project/install/bin/mlir-opt`）
  3. **安装 torch-mlir**（Python 包 + torch-mlir-opt CLI），首选 `pip install torch-mlir`
  4. 若 pip 版本不兼容 torch 2.12，则源码编译 torch-mlir
- **输入**：无
- **产出**：环境信息清单，所有工具链命令可通
- **难点**：低（若 pip 失败则升为高）
- **风险**：torch-mlir 与 PyTorch 2.12 不兼容，需源码编译（耗时 +1~2h）；__高__
- **优先级**：P0（阻塞所有后续工作）

## W2：手写 MLIR 测试用例编写与验证

- **描述**：手写 2 个简单的 Torch Dialect MLIR 文件（matmul、add+relu），用 mlir-opt 验证语法，再下沉到 linalg 验证 lowering pipeline。
- **输入**：W1 的工具链
- **产出**：2 个手写 MLIR 文件 + 验证脚本
- **难点**：理解 Torch Dialect op 语法；中
- **风险**：手写语法错误导致调试耗时；低
- **优先级**：P0（验证工具链可用性）

## W3：简单 PyTorch 模型 → MLIR 导出

- **描述**：编写 Python 脚本，创建 Linear+ReLU 模型，使用 torch_mlir 导出为 Torch Dialect MLIR。
- **输入**：W1 的环境
- **产出**：`export_simple_model.py` + 导出的 `.mlir` 文件
- **难点**：torch_mlir 导出 API 选择；中
- **风险**：API 版本不兼容；中
- **优先级**：P1

## W4：MLIR Lowering + 优化 Pipeline 构建

- **描述**：构建从 Torch Dialect → Linalg → 优化的完整 pass pipeline 脚本。
- **输入**：W2 的手写 MLIR + W3 的导出 MLIR
- **产出**：可复用的 lowering 脚本 `lower_and_opt.sh`
- **难点**：pass 顺序调优；中
- **风险**：下游 dialect 缺失 op 支持导致 lowering 失败；高
- **优先级**：P1

## W5：优化效果对比与记录

- **描述**：对 W3 的简单模型，记录优化前后 IR 的 op 数量、结构变化，形成对比报告。
- **输入**：W4 的 pipeline
- **产出**：优化前后 IR 对比 Markdown 文件
- **难点**：量化指标定义；低
- **风险**：简单模型缺乏优化空间，对比不明显；低
- **优先级**：P2

## W6：GPT-2 模型下载与 Torch MLIR 导出

- **描述**：使用 transformers 下载 GPT-2 small，拆解为 traceable 子图，导出为 MLIR。
- **输入**：W3 的经验 + W1 的环境
- **产出**：`export_gpt2.py` + gpt2*.mlir
- **难点**：大型模型动态控制流处理，可能需要逐 function 导出；高
- **风险**：导出 OOM 或 API 不支持 GPT-2 的某些 op；高
- **优先级**：P2

## W7：GPT-2 MLIR Lowering + 优化

- **描述**：对 GPT-2 导出的 MLIR 执行 W4 的 pipeline，必要时按 function 拆分处理。
- **输入**：W6 的 MLIR + W4 的 pipeline
- **产出**：优化后的 GPT-2 IR + 过程日志
- **难点**：大规模 IR 的 pass 性能，可能需要分 function 处理；高
- **风险**：部分 op lowering 不完整导致 pass 中断；高
- **优先级**：P3

## W8：最终验证报告

- **描述**：汇总两个阶段的验证结果，书写总结报告。
- **输入**：W1～W7 全部产出
- **产出**：`总结报告.md`
- **难点**：低
- **风险**：低
- **优先级**：P3

# Phase 3: Linalg 层聚焦 — GPU / Pass / Kernel (2026-07-13+)

> 核心认知：所有模型最终都 Lowering 到同一套 Linalg IR。上层模型（GPT-2/Qwen）只是验证素材，真正的研究对象是 Linalg 层及以下的编译优化。

## W9：Linalg → GPU/LLVM Lowering ✅ (已完成 2026-07-13)

- **描述**：
  1. ✅ 理解 MLIR 的 GPU dialect 和 lowering pipeline
  2. ✅ 将 GPT-2 的 Linalg IR 继续 lowering 到 GPU/LLVM
  3. ⏳ 在 4060 上编译执行（待 W12 LeetGPU 后完成）
- **输入**：W6~W7 的 GPT-2 Linalg IR
- **产出**：`tools/lower_to_gpu.sh` + `mlir/lowered/gpt2_dynamic_gpu.mlir` (832 kernel, 27032行)
- **实际结果**：Pipeline 打通（bufferize→parallel→gpu-map→gpu-convert→kernel-outline），语法验证通过
- **遗留问题**：无 tiling → 832 kernel 全是 1 block × 1 thread，性能低
- **优先级**：P0

## W10：自定义 Linalg Pass 开发 ✅ (已完成探索 2026-07-13)

- **描述**：
  1. ✅ 探索 scf-parallel-loop-tiling（小 matmul 可用，GPT-2 上破坏 GPU 映射）
  2. ✅ 测试 transform dialect tiling（该版本 mlir-opt 缺 linalg-tile op）
  3. ⏳ 完整自定义 Pass 开发（需源码编译 MLIR）
- **实际产出**：`passes/CountLinalgOps/`（.cpp + CMakeLists + build 脚本）+ `mlir/handwritten/tile_matmul_transform.mlir`
- **关键发现**：MLIR pass plugin API = `mlirGetPassPluginInfo()` 入口点，编译为共享库后 `--load-pass-plugin` 加载；Transform dialect tiling 需正确匹配根类型和返回数量
- **优先级**：P1

## W11：Kernel 性能基准测试

- **描述**：
  1. 用 IREE 编译器将优化前后的 IR 编译执行
  2. 手写 Triton kernel 实现相同功能
  3. 对比 MLIR 自动生成 vs 手写 Triton vs PyTorch 原生的性能
- **输入**：GPT-2 Linalg IR
- **产出**：`benchmarks/results/gpt2_kernel_bench.csv` + 分析报告
- **难点**：IREE 环境配置、Triton on 4060；高
- **风险**：IREE 兼容性、Triton 安装问题；高
- **优先级**：P1

## W12：LeetGPU 集成

- **描述**：
  1. 配置 GPU 加速环境（CUDA/cuDNN/Triton）
  2. 确保 MLIR 的 GPU pipeline 可在 4060 上正常编译运行

- **输入**：现有环境 + 4060 GPU
- **产出**：LeetGPU 环境配置文档
- **难点**：CUDA 工具链配置；低
- **风险**：低
- **优先级**：P1
