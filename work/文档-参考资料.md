## 二、系统性教材 / 课程

- **[mlc.ai](https://mlc.ai/zh/) — 陈天奇《Machine Learning Compilation》（有中文版）**【教材】
  系统讲融合、TensorIR、自动调度，与 TVM 一脉相承。最贴合本项目"学习编译器优化原理"的目标。
- **[mlsysbook.ai](https://mlsysbook.ai/) —《Machine Learning Systems》**（Vijay Janapa Reddi, Harvard）【教材】
  免费在线书，覆盖硬件 → kernel → 编译器全栈。
- **[How to Scale Your Model](https://jax-ml.github.io/scaling-book/)**（Google / JAX 团队）【教材】
  roofline、并行、kernel 效率，偏系统侧。

## 三、一手论文（源头）

| 论文 | 会议/年份 | 为什么对本项目重要 |
|---|---|---|
| **Halide**: *A Language and Compiler for Optimizing Parallelism, Locality, and Recomputation* | PLDI 2013 | **融合（fusion）作为"调度选择"概念的源头**，理解"融合为何省访存"的根 |
| **MLIR**: *Scaling Compiler Infrastructure for Domain Specific Computation* | CGO 2021 | 整条链的架构依据 |
| **TVM**: *An Automated End-to-End Optimizing Compiler for Deep Learning* | OSDI 2018 | 自动调度 / 融合的开山之一 |

| **FlashAttention** | NeurIPS 2022 | 手写 kernel 打败通用编译器的标志性案例 |

## 四、专答：「自动融合 vs 手写 kernel」

这是本项目**尚未量化**的开放问题（见 `work/task/任务&讨论-能解决的业内问题.md` 方向三），最相关的参考：

- **[The Deep Learning Compiler: A Comprehensive Survey](https://ar5iv.labs.arxiv.org/html/2002.03794)**（Li et al., TPDS 2020, arXiv:2002.03794）【论文】
  将算子融合定位为 **block-level 前端优化** —— 本项目的 `linalg-fuse-elementwise-ops` 正属此类。
- **[Operator Fusion in XLA: Analysis and Evaluation](https://ar5iv.labs.arxiv.org/html/2301.13062)**（arXiv:2301.13062）【论文】
  拆出 XLA 的**四种融合策略**（Instruction Fusion / Fusion Merger / Multi-Output Fusion / Horizontal Fusion）。可据此判断本项目的 pass 覆盖了哪几类、缺哪几类。
- **[PyTorch dev-discuss（TorchInductor 设计）](https://dev-discuss.pytorch.org/)**【官方】
  生产级"自动融合 + 代码生成"的实现说明。
- **[《深度学习编译优化技术综述》](https://www.jos.org.cn/jos/article/abstract/7649)**（软件学报）【论文】
  中文语境下最系统的一份。

## 五、建议阅读顺序

贴合本项目推进顺序：

1. **Halide 论文 § fusion** → 建立"融合 = 访存优化"的直觉
2. **MLIR Linalg 文档 + Passes 索引** → 搞清 `linalg-fuse-elementwise-ops` 做了什么、边界在哪
3. **mlc.ai 课程** → 把自动调度 / 融合体系化
4. **XLA 融合论文 + TorchInductor 文档** → 回答"自动 vs 手写"
5. **Triton 文档** → 回到手写部分
