---

## 一、核心认知转变

### 原始思路

```
GPT-2  → 验证优化
Qwen   → 验证优化  →  多模型对比 → 找架构差异
Llama  → 验证优化
BERT   → 验证优化
```

### 问题

所有模型 Lowering 到 Linalg 后都是 generic / matmul / fill / transpose 的组合，差异极小。多花几周时间，可能只得到"SwiGLU 分解后多几个 elementwise op，融合率高 2 个百分点"这类增量结论。

### 新认知

> 所有模型最终都 Lowering 到同一套 Linalg/Arith/SCF IR。上层（GPT-2/Qwen/Llama/DeepSeek）只是"测试素材"，不是核心研究对象。真正的战场在 Linalg 这一层。

```
所有模型 (GPT-2/Qwen/Llama/DeepSeek)
         ↓  (最终都收敛)
    Torch Dialect MLIR
         ↓  Lowering
  ┌──────────────────────────┐
  │  Linalg / Arith / SCF     │  ← 🎯 研究对象
  │  - 计算图 (fuse/split)    │
  │  - kernel (tile/distrib)  │
  │  - 内存层次 (vectorize)    │
  └──────────────────────────┘
         ↓  Lowering
     GPU / LLVM / SPIR-V
```

上层的各种框架/特性说到底都要 Lowering 下来。我们处理的是 Lowering 之后的 IR。

### 关键依赖

- **Linalg**：所有计算最终的表达形式
- **计算图**：op 之间的依赖和融合关系
- **kernel**：实际在 GPU 上执行的代码单元
- **LeetGPU**：GPU 加速基础设施，必不可少

## 二、新 Phase 3 方向

| ID | 任务 | 核心问题 |
|------|------|------|
| **W9** | Linalg → GPU/LLVM Lowering | 如何从 Linalg 生成可执行的 GPU kernel？ |
| **W10** | 自定义 Linalg Pass | Tiling/Fusion/Vectorization 如何影响性能？ |
| **W11** | Kernel 性能基准 | MLIR 自动生成 vs 手写 Triton，差距多大？ |
| **W12** | LeetGPU 集成 | GPU 加速的统一基础设施 |

### GPT-2 的角色

GPT-2 已跑通全链路，作为 Linalg IR 的**输入素材**和**验证集**足够。不再需要多模型导出。
