## 二、项目目标

测试 MLIR 对 PyTorch 模型加速优化的效果，分两阶段实施：
1. **阶段一**：简单 PyTorch 模型 → Torch MLIR → MLIR 优化 → 验证
2. **阶段二**：GPT-2 模型 → Torch MLIR → MLIR 优化 → 验证

## 三、关键发现

### 阶段一发现（2026-06-04）

1. **Nightly wheel 可用**：`torch-mlir` 有每日构建的预编译 wheel，无需源码编译，安装仅需 1 分钟。
2. **导出 API**：正确入口是 `torch_mlir.fx.export_and_import()`，不是 `torch_mlir.compile()`。
3. **验证工具分工**：系统 `mlir-opt` 不含 Torch 方言，无法直接验证 Torch Dialect MLIR。应使用 `torch-mlir-opt` 进行 Torch Dialect 验证和 lowering。
4. **优化效果可见**：`--linalg-fuse-elementwise-ops` 成功将 add+relu 两个 `linalg.generic` 融合为单 kernel。
5. **Pass 选择有反效果**：`--linalg-generalize-named-ops` 将 `linalg.matmul` 等命名 op 展开为 `linalg.generic`，op 计数反而增加（14%~33%）。最优策略是 `fuse-elementwise-ops + canonicalize + cse`。

### 阶段二发现（2026-07-10）

6. **GPT-2 裸导出零干预**：极小 GPT-2 (2层/128维) 直接导出成功，0 个 `torch.operator` 兜底节点。GELU、LayerNorm、SDPA 等所有特殊算子均被默认分解表自动处理，无需任何手动分解。
7. **大模型优化效果更显著**：GPT-2 优化后 linalg ops 降低 52.3% (149→71)，远超简单模型平均 25.8%。原因是大模型有更密集的 matmul+elementwise 组合，融合机会多。
8. **matmul→generic→融合的正向链路**：`canonicalize` 自动将 `linalg.matmul` 转为 generic（带 reduction），然后 `fuse-elementwise-ops` 将其与后续 elementwise op 融合为宏内核。在简单模型中这被视作反效果（W5 #5），但在 GPT-2 中净效果为正——72 个 matmul 全部被融合。
9. **规模递增效应**：标准 GPT-2 (12层) 的优化比例 58.5% > 极小 GPT-2 (2层) 的 52.3% > 简单模型平均 25.8%，表明模型越大、融合机会越多、优化效果越显著。

## 四、技术架构

```
PyTorch 模型 → torch_mlir (torchscript/torch.export) → Torch Dialect MLIR
  → torch-mlir-opt (lowering) → Linalg/SCF/Arith Dialect
  → mlir-opt (优化 passes) → 优化后的 MLIR
  → 验证 (mlir-opt --verify-diagnostics / 手写对比)
```

## 五、难点分析

### 困难 1：Torch MLIR 导出路径选择
- **问题**：torch_mlir 提供两条路径：基于 TorchScript（旧，`torch.jit.script/trace`）和基于 `torch.export`（新，FX Graph）。后者对 Python 的动态特性支持有限。
- **方案**：
  - 阶段一优先使用 `torch.jit.trace`（稳定，易于调试），模型简单不涉及动态控制流。
  - 阶段二 GPT-2 使用 `torch.export`（标准导出路径），若失败则回退到 TorchScript。
- **验证**：对比两种路径导出的 MLIR 文本结构完整性。

### 困难 2：MLIR Lowering Pass Pipeline 构建
- **问题**：Torch Dialect → Linalg 的下沉链路长，依赖多个 pass，顺序错误会导致失败。
- **方案**：参考 torch-mlir 自带的 `RefBackend` pipeline，简化关键路径：
  `torch-backend-to-linalg-on-tensors-backend-pipeline` → canonicalize → cse
- **验证**：输入手写 Torch dialect MLIR，逐 pass 运行确认不报错。

### 困难 3：优化效果量化
- **问题**：MLIR 生成后如何判断优化有效？
- **方案**：
  - 统计关键 op 数量（如 linalg.matmul → linalg.generic，scf.for 融合）
  - 对比优化前后 IR 的 op 数量、内存分配次数
  - 使用 `mlir-opt --mlir-print-ir-before-all --mlir-print-ir-after-all` 追踪变更

### 困难 4：GPT-2 模型 IR 规模过大
- **问题**：GPT-2 生成的 MLIR 文件可能数千行，阅读/调试困难。
- **方案**：使用 function-by-function 切分，只聚焦 attention 和 FFN 子图。

## 六、验证方法

### 验证层级

| 层级 | 工具 | 命令 | 验证对象 |
|------|------|------|----------|
| 语法验证 | `torch-mlir-opt --verify-diagnostics` | `torch-mlir-opt file.mlir` | Torch Dialect MLIR 语法 |
| 结构验证 | `torch-mlir-opt --mlir-print-ir` | lowering 前后 diff | lowering 完整性 |
| Linalg 验证 | `mlir-opt --verify-diagnostics` | `mlir-opt lowered.mlir` | 下沉后的 Linalg IR |
| 功能验证 | `torch.allclose` | Python 脚本 | 原始模型 vs MLIR 执行 |

### 手写 MLIR 验证（阶段一前置）

**样本数据**：手写一个 2×3 × 3×2 矩阵乘法的 Torch Dialect MLIR 文件。

**验证命令**：
```bash
# 1. 语法检查（必须用 torch-mlir-opt，系统 mlir-opt 不含 Torch 方言）
torch-mlir-opt --verify-diagnostics test_matmul.mlir

# 2. 下沉到 linalg
torch-mlir-opt --torch-backend-to-linalg-on-tensors-backend-pipeline test_matmul.mlir

# 3. 优化（用 mlir-opt，此时 IR 已是 Linalg/Arith/Tensor 方言）
mlir-opt --linalg-fuse-elementwise-ops --cse --canonicalize test_matmul_lowered.mlir
```

### PyTorch 简单模型验证（阶段一）

**样本模型**：`Linear(2,3) + ReLU` 的序列模型。

**验证命令**：
```bash
# 1. 导出 MLIR
python export_simple_model.py  # 输出 simple_model.mlir

# 2. 语法验证
mlir-opt --verify-diagnostics simple_model.mlir

# 3. 下沉 + 优化（同上 pipeline）

# 4. Python 端功能验证
python verify_functional.py  # torch.allclose 对比
```

### 8.2 Linalg → GPU 全链路

```
Linalg IR (动态 shape)
    │  --linalg-tile-and-fuse
    ▼
Linalg (tiled, scf.for 出现)
    │  --convert-linalg-to-parallel-loops
    ▼
SCF (parallel loops, 可映射到 GPU)
    │  --gpu-map-parallel-loops
    ▼
GPU Dialect (gpu.launch, gpu.func)
    │  --convert-parallel-loops-to-gpu
    │  --convert-scf-to-cf
    ▼
LLVM / SPIR-V (可执行)
```
