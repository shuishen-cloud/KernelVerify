# 优化效果对比报告

> 阶段一输出，基于 `tools/lower_and_opt.sh` 的 default 策略（`fuse-elementwise-ops + canonicalize + cse`）

## 一、总览

| 模型 | 类型 | linalg ops 前 | linalg ops 后 | 降低 |
|------|------|:---:|:---:|:--:|
| add_relu | 手写 | 4 | 2 | **50%** |
| conv_bn_relu | 导出 | 18 | 12 | **33%** |
| linear_relu | 导出 | 7 | 5 | **28%** |
| two_layer_mlp | 导出 | 12 | 10 | **16%** |
| matmul | 手写 | 2 | 2 | 0% |
| simple_model | 导出 | 7 | 5 | **28%** |

**平均降低：25.8%**

## 二、策略对比

| 策略 | Pass 组合 | 6 模型平均效果 |
|------|-----------|:--:|
| `light` | canonicalize + cse | +0% (无效) |
| **`default`** | **fuse-elementwise-ops + canonicalize + cse** | **-25.8% ✅** |
| `aggressive` | default + generalize-named-ops + eliminate-empty | +6.3% (反效果) |

**结论**：`linalg-fuse-elementwise-ops` 是核心有效 pass；`linalg-generalize-named-ops` 破坏命名 op 结构，不应使用。

## 三、典型优化案例分析

### 3.1 add_relu — 最佳案例（50% 降低）

**优化前**（2 个 kernel）：
```mlir
// Kernel 1: elementwise add
%1 = linalg.generic { addf }
    ins(%arg0, %arg1) outs(%0)

// Kernel 2: relu
%2 = linalg.generic { cmpf ugt; select }
    ins(%1) outs(%0)
```

**优化后**（1 个融合 kernel）：
```mlir
// 单 kernel: add + relu 融合
%1 = linalg.generic { addf → cmpf ugt → select }
    ins(%arg0, %arg1) outs(%0)
```

**效果**：2 个 kernel → 1 个 kernel，消除中间临时 tensor，减少内存分配。

### 3.2 conv_bn_relu — 最大规模优化（33% 降低）

IR 行数：83 → 90（优化后行数增加是因为融合后代码更密集）

**融合前**（BN 链 + Conv + ReLU 各独立的 linalg.generic）：
```
linalg.conv_2d_nchw_fchw        # conv
linalg.generic { subf }          # BN: x - mean
linalg.generic { mulf + mulf }   # BN: scale × (x - mean) × inv_std
linalg.generic { addf }          # BN: + bias
linalg.generic { cmpf; select }  # relu
```
加上 BN 的中间计算（add_epsilon, sqrt, div），共 7 个 generic + 1 个 conv。

**融合后**：BN 统计量预计算被提取，conv 的统计量预计算内联，核心计算融合为：
```
linalg.conv_2d_nchw_fchw        # conv (不可融合的命名 op)
linalg.generic { subf; mulf; mulf; addf; cmpf; select }  # 融合核
linalg.generic { ... }           # 预计算统计量 (×3)
```
18 op → 12 op，融合了 6 个独立 kernel 为 1 个 macro kernel。

### 3.3 matmul — 无可优化空间（0%）

单 op 模型，`linalg.matmul` 是命名 op，没有可融合的相邻 elementwise op。

## 五、局限

1. **简单模型优化空间有限**：matmul 等单 op 模型无融合机会。
2. **Conv named op 不可融合**：`linalg.conv_2d_nchw_fchw` 是命名 op，不与后续 elementwise 融合（未启用 `generalize-named-ops` 时）。
3. **无循环层融合**：当前简单模型无 `scf.for` 循环，无法测试循环融合/分块优化。
4. **这是静态 IR 优化**：未涉及运行时/JIT 优化，实际执行性能需 IREE 等 runtime 测量。
